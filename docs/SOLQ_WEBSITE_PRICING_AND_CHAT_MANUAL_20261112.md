## 견적 계산·승인 규칙
1. 접수번호와 내부 application_id를 연동하고 업종, 페이지, 기능, 참고 URL, 수정 범위를 구조화한다.
2. 상품 기본가 + 추가 페이지/기능/연동/디자인/유지보수 개별 견적을 산정하되 자동 견적은 **제안**으로만 표시한다.
3. API·호스팅·도메인·이미지 라이선스·결제수수료·부가세는 구분 표기하고 비용 상한·잔액·실행 횟수 확인 전 유료 작업 차단.
4. 고객에게 견적과 포함·제외·수정·납기·유지보수 조건을 제시한다. 고객 동의 후 착수금은 기존 수동 확인 체계로 처리한다. 신규 홈페이지 상품의 착수금 비율은 별도 승인 전 자동 적용 금지.
5. 관리자가 입금 확인 및 **별도 제작 승인**을 서버에서 완료한 경우에만 유료 워커를 실행한다.
6. 고객별 불변 내부 ID, 안전한 고객 인증, RLS 및 저장소 격리, 서버 측 승인·예산 재검증을 필수로 한다. 이름·접수번호만으로 로그인시키지 않는다.
7. 고객과 AI 채팅으로 요구사항을 구체화하되 계약 범위를 벗어난 요청은 추가 견적과 동의를 거친다. 무제한 자동 수정 금지.
8. 격리된 고객별 코드·미리보기에서 빌드/보안/모바일 검사 후 전달. 외부 공개·운영 배포·실제 고객 알림은 별도 승인 전 금지.
9. 작업별 증거: 고객 ID, 승인 이벤트, 견적 버전, AI 호출 원가, 수정 이력, 테스트, 미리보기 접근 로그를 보관한다. 비밀키/개인정보는 공개 저장소에 저장하지 않는다.

## UI·AI 워커 개발 수용 기준
- 홈페이지 우하단 상담사 버튼이 스크롤과 무관하게 고정되고, 키보드·모바일에서도 본문과 주요 CTA를 가리지 않는다.
- 채팅창 열기/접기, 작은 화면에서 높이 제한·내부 스크롤·접근성, 오류 및 연결 상태 표시.
- 무료 방문객은 일반 상담만. 승인 고객은 안전한 인증 후 자신의 대화·시안·작업만 조회.
- 프런트엔드의 상태 값만 믿지 않고 서버에서 결제 확인+별도 제작 승인+비용 한도+고객 소유권 확인.
- 미리보기는 고객별 격리된 샌드박스/별도 출처, 임의 생성 HTML의 스크립트 실행 금지 또는 엄격 격리.
- 실제 운영 데이터 보존, 개발 브랜치·합성 고객 데이터 테스트, 운영 배포 NO-GO 유지.
