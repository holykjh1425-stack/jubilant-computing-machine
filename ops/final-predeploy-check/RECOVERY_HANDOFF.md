판정: **추가 검증 필요 — 배포 보류**. 문서·의존성 확정은 완료했지만 실제 다중 세션, 실인증 통합, 운영 백업 복원은 완료하지 않았다. 이 문서는 배포 실행 승인이 아니다.

## 실행 기록과 재개 경계

이 대화의 이전 도구 기록에서 apt 설치는 exit 100과 setgroups/setegid/seteuid 오류로 끝났다. 당시 UID/GID 매핑은 0 하나만 허용했다. 패키지 관리자가 _apt 등 다른 ID로 전환하려다 실패한 것이 설치 오류의 직접 원인이다. 이후 npm 대체 패키지 설치는 exit 0으로 끝났지만 initdb/postgres/독립 연결 테스트를 실행한 도구 기록은 없다. 사용자 중복 실행 방지 지시 후 최종 보고로 해당 응답이 종료됐다. 이것은 이 대화의 기록이며 다른 세션 종료를 증명하지 않는다. 화면 깜빡임과 권한 오류 사이의 인과관계, 플랫폼 실행 ID·취소 원인은 확인 불가다.

이번 확인에서도 PostgreSQL 관련 실행 프로세스가 발견되지 않았다. /tmp/solq-native-pg와 /tmp/solq-isolated-runtime은 현재 존재하지 않는다. 따라서 이전 설치물을 재사용할 수 없으며 '대체 실행 환경 복구 완료'로 보고할 수 없다. 설치·초기화·테스트를 재실행하지 않았다. 다른 Work 세션의 종료 증거와 공통 실행 잠금이 없으므로 경합 가능한 작업은 보류했다. 운영 PostgreSQL은 17.11이므로 향후 격리 환경도 17 계열로 맞추는 것이 바람직하다. 단일 연결 PGlite 결과는 독립 연결 검증으로 대체하지 않는다.

다음 실제 실행의 선행 조건: 원래 실행의 완료/취소/종료 근거를 확보하고 해당 검증의 단독 담당 세션을 확정한다. 서로 다른 환경에서 로컬 프로세스/로컬 잠금만 검사하는 것으로 전역 중복 방지가 성립하지 않는다. 조건 충족 전에는 설치와 검증을 시작하지 않는다.

## 승인 후 적용 순서와 중단 조건

1. 먼저 남은 승인 전 검증과 보호된 운영 백업 복원 검증을 완료한다. 실제 배포 자산·호스팅 설정·CSP/캐시·Edge 배포 버전 및 함수/트리거/ACL/RLS/cron 정의, 일관된 DB 백업을 보호된 장소에 보존한다. 공개 저장소에 DB/인증/비밀정보를 넣지 않는다. 기존 code-recovery-result.json의 23개 파일 복원 시험은 코드 전용이며 운영 DB 백업 증명이 아니다.
2. read-only-preflight.sql로 최신 집계·관계·인덱스 정의/유효성·RLS를 확인한다. 과거 기준과 다르면 신규 정상 접수 여부를 조사하고 데이터 삭제로 숫자를 맞추지 않는다. 신청별/계획별 unique의 실제 컬럼·조건·validity가 예상과 다르면 중단한다.
3. DB 가드는 승인 후 **단일 트랜잭션**에서 lock_timeout 3s / statement_timeout 30s를 두고 실행한다. 재검사와 가드 설치 사이에 경쟁 쓰기가 없도록 대상 테이블을 정해진 순서(applications → ai_work_plans → orchestrator_jobs)로 짧게 잠그고 재검사한다. lock timeout·index 충돌·예상 밖 trigger/함수 정의면 전체 rollback한다. 정상 워커를 장시간 정지하거나 cron을 무작정 비활성화하지 않는다. 잠금 획득 실패 시 다음 창으로 연기한다. 실제 소요시간은 아직 미측정이다.
4. 가드 성공 후 nexus-orchestrator 패키지를 반영한다. 구 신청 ID/계획 ID 등록은 409, 인증 누락·비관리자·DB 조회 실패는 차단되어야 한다. API 점검에 운영 고객 키로 쓰기 요청을 보내지 않는다. 승인된 격리 환경에서 먼저 수행하고 운영은 비변경 경로로 상태 확인한다.
5. 관리자 9개 파일 묶음을 원자적으로 교체한다. HTML과 JS/CSS가 서로 다른 버전으로 노출되지 않게 한다. HTML 재검증/no-store 및 자산 해시 기반 버전 URL 또는 호스팅 캐시 무효화를 준비한다. config/SDK 포함 의존성 해시 일치, 최종 URL /admin 및 /admin.html 리다이렉트, 응답 MIME/CSP/ETag/Cache-Control과 새로고침 결과를 확인한다. 실제 배포 CSP/캐시는 아직 통과하지 않았다.
6. 열린 구 관리자 탭은 재접속하도록 안내한다. 서버 가드는 구 탭의 등록 요청도 거부해야 한다. 브라우저 Network에서 로그인·목록·실제 30초 주기 조회의 업무 쓰기 0회를 확인한다. Auth 토큰 갱신의 POST와 업무 데이터 쓰기를 구분한다. 6단계 표시, 명시적 상태 저장, 비관리자 거부 및 RLS를 검증한다. 상태 저장 동적 테스트는 격리 합성 데이터로 수행한다.

어느 단계든 중복 생성, 조회 중 업무 쓰기, 권한 우회, 정상 무료 워커 실패 증가, 고객 연결 변경, 승인 없는 제작 호출이 관측되면 다음 단계를 멈춘다. 운영 수치를 맞추기 위한 삭제·재연결은 하지 않는다.

## 롤백 계획과 한계

가드 설치 트랜잭션 실패: 전체 rollback. API 또는 자산 장애: 관리자 유지보수/검증된 조회 전용 화면으로 전환하고 데이터 보존형 서버 가드는 유지한다. 쓰기 자동 생성이 있는 구 관리자 JS를 재노출하지 않는다. 새 가드를 제거하거나 구 서버를 복구하는 것은 방어 약화를 수반하므로 별도 검토·승인한다. 함수 복구에는 백업한 정확한 정의·소유자·ACL·트리거 연결을 사용한다. 전체 DB 과거 복구로 배포 후 신규 신청을 유실시키지 않는다.

원래 API/자산으로 돌아가는 것과 '이전 정상 안전 버전'으로 돌아가는 것은 다르다. 안전 버전의 운영 패키지 및 보호된 DB 백업을 아직 확보·복원 검증하지 못했으므로 **운영 롤백 검증 완료로 판정하지 않는다**. 이번에 확인한 것은 배포 후보의 파일 존재/해시와 문서화된 복구 순서다.
