## 완료: 현재 운영 코드 비교
- admin.js와 free-workflow.js GET 모두 HTTP 200. admin.html은 307로 /admin에 이동한 뒤 HTTP 200.
- 운영 admin.js는 processNew()에서 free.plan()/free.assign()을 호출하고 30초 폴링에 연결한다. planControls()도 기준 시각 이후 신청을 렌더링할 때 두 함수를 호출한다. 따라서 로그인 후 목록 진입·새로고침·폴링이 등록 경로를 실행할 수 있다. 실제 인증 화면에서 재현해 데이터를 쓰지는 않았다.
- 운영 free-workflow.js는 계획 ID를 idempotency_key로 조회·submit하고 tick을 호출한다. 현재 서버 free_cycle은 신청 ID를 키로 사용하며 application_id/free_plan_id를 저장한다.
- 후보 admin.js는 processNew와 생성 버튼/자동 act 경로를 제거하고 snapshot만 조회한다. 후보 free-workflow.js는 신청 ID로 읽고 계획·작업 연결 일치를 검사하며 생성 함수를 제공하지 않는다.
- 운영 command 함수는 service_role 및 관리자 actor를 검사하지만, submit INSERT에 application_id/free_plan_id가 없고 키 중복만 검사한다. 현재 orchestrator_jobs에는 후보 연결 가드 트리거가 없다. 서비스 역할이라는 사실만으로 승인된 고객별 경로가 보장되지는 않는다.
- 링크 가드 후보는 과거 계획 ID 키 등록, 부분 연결·타 고객 연결·키 불일치·연결 재할당·미연결 실행을 차단한다. 기존 행 수정은 하지 않는다. UI와 서버 가드를 함께 반영하기 전 위험 차단 완료로 판정하지 않는다.

## 배포 전 점검
- CSP: 운영과 후보 모두 script-src self, connect-src 프로젝트 Supabase 원점이다. 후보는 같은 원점의 plan-view.js, quote-panel.js, CSS를 추가하므로 파일 누락 없는 선택적 패키징이 필요하다. 정적 검사이며 실제 배포 CSP 실행 검증은 미완료.
- 캐시: 현재 JS는 public, max-age=0, must-revalidate 및 ETag 응답. 열린 탭의 메모리 내 구 스크립트를 교체하지는 않는다. 승인된 반영 시 관리자 탭 종료/재접속, 배포 자산 해시·스크립트 순서 확인이 필요하다.
- 100명 구조 평가: free_cycle은 전역 트랜잭션 advisory lock, 행 잠금/SKIP LOCKED, 계획 unique 및 부분 작업 unique 인덱스를 사용한다. 전역 잠금은 중첩 워커를 제한하지만 처리량 병목도 된다. 한 호출의 처리 한도는 50건이므로 100건을 한 주기에 끝낸다고 보장하지 않는다. 관리자 25건 조회와 30초 개별 폴링의 다수 요청도 부담이다. 성능 SLA 미확정.
- 잠금 순서/교착 재시도는 실제 다중 세션 검증 필요. PostgreSQL 공식 문서: https://www.postgresql.org/docs/current/explicit-locking.html
- 실제 휴대전화 접근 장치 없음. 이전 모바일 뷰포트 검사 결과만 존재하며 실물 검증 완료로 표시하지 않는다.
- 보안 진단에는 기존 공개 접수/조회 SECURITY DEFINER 함수 경고와 유출 비밀번호 보호 비활성 경고가 있다. 이번에 변경하지 않았으며 의도된 익명 기능인지 별도 검토 대상이다.
- 원격 변경 파일에서 키·JWT·개인키·DB URI·개인 연락처 패턴 탐지 0건. 신규 테스트는 가상 데이터만 사용. 운영 행 ID·고객 원문·세션·접속정보는 업로드하지 않는다.

## DB 변경 계획과 복구
운영 변경 SQL은 기존 후보 link-guard.sql, ../free-plan-automation/quote-evidence.sql, quote-deposit-guard.sql에 있다. 이번에는 적용하지 않았다.
- 영향: 연결 가드는 구 브라우저 등록과 미연결 queued/running/completed 전환을 거절한다. 견적 가드는 새 원장 3개/RPC/트리거와 기존 record_quote 교체를 포함하고, 증거 없는 기존 제작 경로를 차단한다.
- 보존: 기존 신청/계획/미연결 작업을 삭제·재할당·자동 이관하지 않는다. 기존 증거의 자동 인정도 하지 않는다.
- 승인 전 보호된 장소에 현행 호스팅 자산, 함수 정의/ACL/트리거/RLS와 고객 데이터의 복구 가능한 백업을 확보하고 복구 시험해야 한다. 이번 읽기 전용 점검은 복구 가능한 백업 확보를 대신하지 않는다.
- 적용 시 SQL 전체를 트랜잭션으로 처리하고 실패 시 rollback. 배포 후 오류는 제작 제공자 disabled, 조회 전용 유지보수 화면을 유지하면서 승인된 백업 기준으로 변경 항목만 복구한다. 조회로 쓰는 구 관리자 JS를 그대로 재노출하지 않는다. 새 증거 원장은 보존한다.
- 이번 브랜치 변경의 복구는 신규 테스트/보고서만 후속 revert. 강제 push/운영 롤백은 하지 않는다.

## 다음 및 승인 필요

4. 제작 기능 활성화·실제 견적 발송·입금 확인·고객 제작·유료 API는 별도 승인 대상이다. 이번 변경을 이들 승인으로 해석하지 않는다.

종료 사유: 현재 운영 읽기 전용 점검과 추가 격리 검사는 완료했으나, 관리자 세션·미배포 견적 API/원장·다중 세션 DB·실물 장치 제한으로 통합 검증을 완료할 수 없다. 운영 위험 잔존을 명시하고 작업을 종료한다.
