## 오류·해결 및 미완료

1. 기본 Playwright 브라우저 다운로드가 손상된 ZIP으로 실패했다. 동일 시도 반복을 중단하고 npm 배포 Chromium 바이너리로 대체해 실행했다. 첫 테스트의 불투명 about:blank origin으로 세션 저장소 접근이 실패한 문제는 격리 qa.invalid origin으로 수정했다. 초기 한글 글꼴 누락도 환경에 Noto 글꼴을 설치해 해결했다. 프로젝트 런타임 의존성은 변경하지 않았다.
2. 운영 관리자 화면은 수정 전 코드다. 조회 시 중복 생성 방지는 후보 화면에서 확인했으며 운영 반영 완료로 주장하지 않는다. 인증된 운영 화면을 재현 목적으로 열지 않았다.
3. 실제 관리자 인증 서버와 후보 API·SQL을 연결한 통합 실행, 실물 휴대전화 확인은 미완료다. 브라우저 검증은 모의 인증/응답이고 CSP·스크립트 배포/캐시까지 검증한 것은 아니다.
4. 100개 실제 DB 동시 세션 부하, 잠금 경합/성능 SLA는 미검증이다. 이번 격리 DB 검증을 운영 동시 접속 성능으로 해석하면 안 된다.
5. 관리자 외부 원본 확인 방식의 증거 등록이다. 고객 직접 전자서명·실제 은행 자동 조회/입금 확인을 구현한 것은 아니다. 증거 참조는 원본 보관 위치이며 원본 진위는 관리자가 대조한다.
6. 기존 공개 SECURITY DEFINER 3개와 유출 비밀번호 보호 비활성 경고를 재확인했다. 신규 변경의 원인으로 단정하지 않았고 기존 권한/인증 설정을 변경하지 않았다.

## 보안 위험·적용 순서·롤백

- 배포 전: 현재 호스팅 자산 원본·변경 대상 함수 정의/ACL/트리거 목록·관련 테이블 데이터와 RLS의 복구 가능한 백업을 보호된 위치에 확보하고 복구 가능성을 확인한다. 이번에는 DB 변경이 없으므로 운영 데이터 백업을 새로 실행하거나 완료했다고 주장하지 않는다.
- 명시적 승인 후: 실행 제공자 disabled 유지 → 관리자 진입을 임시 읽기 전용 유지보수 화면으로 제한 → 관련 SQL을 하나의 트랜잭션에서 적용·검증 → API 배포 → 후보 UI 자산만 반영 → 읽기 전용 운영 재검증. 견적 동의 기록/실제 입금·승인·제작 시험은 별도 허가 없이는 하지 않는다.
- 원장 적용 시 기존 동의가 있는 고객은 최신 원장에 자동 편입되지 않아 제작이 차단된다. 현재 동의 기록은 0건이나 적용 직전 다시 확인한다. 기본값/자동 백필로 우회하지 않는다.
- 가드 추가에는 고객별 잠금이 포함된다. 기존 제작 함수와의 다중 세션 잠금 순서·교착 재시도는 운영 부하 검증 전 확정하지 않는다. 승인·제작 제공자 활성화 범위에 포함하지 않는다.
