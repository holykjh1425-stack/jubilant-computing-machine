## 1. 확정한 관리자 조회 방식

기존 후보의 조회 전용 구조를 유지한다. 로그인·고객 선택·새로고침·30초 신규 접수 알림으로 계획 생성/작업 등록/tick을 호출하지 않는다. 기존 서버 무료 자동 처리 함수와 스케줄은 변경하지 않는다. free_cycle을 중단시키는 approval-gate.sql과 그 RPC 클라이언트는 제외한다.

## 2. 무료 계획의 저장·조회·고객 제공 준비

저장은 기존 승인된 서버 무료 규칙 처리 경로를 유지한다. 조회는 신청 UUID→저장 계획→연결 작업의 정합성을 확인한다. 기존 plan-view.js와 free-workflow.js를 재사용했다.

새 plan-handoff.js와 관리자 컨트롤은 다음 경로를 완성한다.

접수번호별 저장 계획 조회 → 6단계·계획/작업 연결 검사 → 고객 안내문 미리보기 → 관리자 직접 검토 표시 → 복사 직전 실제 권한·최신 계획 재조회 → 일치하는 안내문 복사.

누락·잘못된 접수번호·타 신청 연결·불완전한 6단계·권한 만료·선택 변경·계획 변경 시 복사를 차단한다. 네트워크 실패 후 자동 생성/재시도/전송하지 않는다. 원문 고객명·연락처·요청 원문·내부 증거 전체를 안내문에 자동 삽입하지 않는다. 단계별 제안 내용은 직접 검토가 필요하다. 안내문은 textContent로 표시하며 HTML로 실행하지 않는다.

고객 제공은 **관리자가 검토한 문안의 수동 안내**까지 준비한 것이다. 접수번호만으로 비로그인 사용자가 개인정보를 조회하는 공개 API를 만들지 않았다. 이메일·문자·메신저 자동 발송, 고객에게 실제 제공, 제작 실행은 수행하지 않았다. 복사는 발송 승인이나 납품 완료가 아니다.

## 3. 견적 동의·입금·제작 승인

기존 quote-panel.js, solq-quote-evidence Edge 후보, quote-evidence.sql, quote-deposit-guard.sql을 재사용한다. 실제 외부 고객 동의 원본을 관리자가 확인해 신청·견적 버전·금액에 연결하는 방식이다. 외부 동의 내용을 가상으로 생성하거나 고객 대신 동의하지 않는다.

quote-flow.js에 async 권한 확인보다 먼저 설정되는 pending 잠금을 추가했다. 동일 클라이언트의 연속/동시 등록을 차단한다. 응답 유실 시 기존 폼은 무효화되어 반드시 최신 증거를 다시 조회한 뒤 판단해야 한다. 자동 재전송하지 않는다. 서로 다른 클라이언트 간 DB 동시성·거래 고유 참조/버전/증거 제약은 기존 서버 후보가 담당하며 기존 증거를 재사용한다.

견적 동의·입금 증거 등록·은행 수동 확인·별도 제작 승인은 각각 분리돼 있다. 고객 입금 알림만으로 확인·제작 승인하지 않는다. 브라우저 가드가 서버/RLS 검증을 대체하지 않는다. 상태 변경/유료 제작 실행은 실검증하지 않았다.

## 6. 2단계 사용자 PC 작업

정확한 PowerShell/Node 실행 명령과 기존 암호화 스크립트 호출은 PHASE2_PC.md에 있다. 요약:

2. 기존 공개키 전용 저장소·암호화 백업 폴더·공식 CA verify-full·DB 연결·pg_dumpall/pg_restore·보호된 기존 복원 대상의 미확인 조건을 확인.
3. 기존 Backup-Encrypted.ps1로 DB/역할을 스트리밍 암호화. 암호문 SHA-256 검증. 이 출력만을 전체 백업 완료로 인정하지 않음.
4. 운영 Edge/Storage/설정/Auth/Vault 복구 범위 보완 후 기존 보호된 비운영 환경에서 실제 복원·건수/내용/RLS/함수/트리거/무송신 확인.
5. 같은 보호된 비운영 환경에서 실제 Auth/Edge/RLS로 새 견적·입금·제작 승인 후보를 연결해 검증. 현재 미확인 환경의 주소/암호를 추정하지 않음.

PC 인증 도구는 공개 설정/SDK를 읽되 키를 출력하지 않는다. 로그인/기존 capabilities/local 로그아웃은 각 1회로 제한하고 외부 호스트·쓰기 RPC·tick·작업 생성·로그인 재시도를 전송 단계에서 거부한다. 토큰은 영구 저장하지 않는다. 로그아웃 후 access token 만료 전 유효성 한계는 공식 문서대로 남는다.

별도 재승인 부족이 차단 원인은 아니다. 사용자 PC의 보안 입력과 보호된 백업/복원 실행 경로가 필요하다. 새 프로그램/서버 설치나 비용 지출은 이 준비물에 포함되지 않는다.

## 7. 3단계 운영 배포 조건

아래 모두를 만족하기 전에는 운영 반영을 하지 않는다.

- 실제 앱 관리자 인증과 기존/새 Edge·PostgREST/RLS 통합 증거. 운영 미배포 API를 먼저 호출하지 않음.
- 최신 전체 암호화 백업·무결성·보호된 실제 복원 성공 증거. 단순 부분 덤프·합성 복원을 전체 복구로 간주하지 않음.
- 실제 운영 구조·기존 기록과 SQL의 호환성 사전 점검. 기존 중복/미연결 기록을 삭제·재연결하거나 데이터 수를 강제로 맞추지 않음.
- 확정된 대상 파일/SQL/Edge를 순서대로 반영하고 버전28 디자인 및 승인된 서버 무료 자동 경로를 보존. 실패 시 새 쓰기 경로를 중단하고 안전한 조회 전용 상태로 유지. 위험한 과거 관리자 자동 생성 파일로 무조건 되돌리지 않음.

이 항목들은 2단계의 실행 결과 확인과 3단계의 배포 직전 점검이며, 이미 완료된 개발을 다시 하자는 뜻이 아니다. 1단계는 후보 코드·무료 격리 검증 범위에서 완료했다. 실제 운영 정상화 판정은 보류다.
