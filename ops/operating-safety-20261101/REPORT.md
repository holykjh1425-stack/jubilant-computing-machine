# SOLQ 운영 안전화 및 홍보 링크 수정 결과

확인일: 2026-11-01 (한국시간). 운영 시스템 반영 판정: **보류**. WordPress 링크 수정: **완료**.

## 완료

- 검증된 후보 커밋 `b55ade9735854b946059080b905801e3f58890d3`를 재사용했다. 기존 SQL·클라이언트·독립 PostgreSQL 연결 동시성 검증은 재실행하지 않았다.
- 관리자 로그인·조회·새로고침·선택 시 생성 호출이 없는 후보 코드를 확인했다. 30초 신규 신청 확인은 읽기 전용이며, 무료 계획 승인과 승인된 계획·작업 생성은 각각 명시적 실행으로 분리되어 있다.
- 신청 및 발행 견적에 연결된 수락 증거, 수동 입금 확인, 별도 제작 승인 조건을 기존 후보에서 확인했다. 고객 입금 알림만으로 확인·제작 승인이 되지 않는다. 이는 후보 코드 및 기존 격리 증거에 대한 확인이며, 운영 적용 성공을 뜻하지 않는다.
- 버전 28 원본을 변경하지 않고 별도 staging-dist를 구성했다. 21개 원본 파일의 Git blob을 고정 커밋과 대조했고, 관리자 의존 파일 누락과 자동 생성 경로를 정적으로 점검했다. 보호 대상 홈페이지·신청·정책 파일은 원본과 동일하다. 관리자 JS 5개의 구문 검사가 통과했다.
- 기존 배포 계획의 19개 파일 목록을 보완해 21개 배포 검토 목록으로 작성했다. 공유 config/vendor 파일은 기존 운영 파일을 유지한다. config 파일의 줄 끝 차이만 허용하며 설정값 변경을 허용하지 않는다.

## 미완료 및 배포 차단 원인

1. 운영에는 새 생성 승인 RPC 및 견적·입금 증거 테이블이 아직 없다. 미배포 API를 운영에서 호출하지 않았다.
2. 현재 Work에서 사용자 Windows PC의 Docker·DB 도구·보호된 세션에 직접 접근할 수 없다. 실제 앱 관리자 인증을 가진 안전한 비운영 Supabase Auth/PostgREST/Edge 통합 증거가 필요하다. 대시보드 Owner 권한이나 SQL 연결을 앱 관리자 인증으로 대신하지 않는다.
3. 최신 전체 암호화 백업과 보호된 격리 복원 증거가 필요하다. 기존 보류 상태를 유지하며 실제 백업·USB 개인키 접근·복원을 수행하지 않았다.
4. 기존 approval-gate.sql은 free_cycle을 수동 승인 방식의 no-op으로 바꾸므로, 유지해야 하는 기존 승인된 무료 자동 처리 경로가 있는지 운영 적용 전 정책을 확정해야 한다. 관련 없는 워커·cron은 임의 삭제하지 않는다.

## 적용 순서와 복구

필수 조건 충족 전에는 아래 SQL·Edge·관리자 파일을 운영에 적용하지 않는다. 사용자의 조건부 실행 승인은 이미 있으므로 같은 승인을 반복 요청하지 않는다. 누락된 실제 검증·백업 증거를 확보한 뒤 변경 범위나 위험이 확대되면 해당 부분에 대해서만 별도 승인을 받는다.

1. 운영 구조와 연결 의존성 읽기 전용 사전 점검 → 암호화 전체 백업 및 격리 복원 증거 확보.
2. 비운영 환경에 manifest 순서로 link-guard.sql → quote-evidence.sql → quote-deposit-guard.sql → approval-gate.sql 검증. 기존 미연결·중복 기록을 삭제·수정하지 않는다. 제약 적용이 기존 데이터와 충돌하면 중단한다.
3. Edge 후보 5개 파일을 검증하고 실제 관리자 인증·권한·오류 복구를 확인한다. 유료 API와 생성 호출을 임의 수행하지 않는다.
4. 승인된 범위의 운영 서버 후보 적용 후 별도 staging의 관리자 10개 파일만 현재 버전 28에 반영한다. 홈페이지 전체나 과거 NEXUS 사이트를 교체하지 않는다.
5. 오류 시 새 쓰기 경로를 중지하고 안전한 조회 전용 관리자 상태를 유지한다. 자동 생성이 있던 예전 관리자 파일로 무조건 되돌리지 않는다. DB 컬럼·증거 테이블을 파괴적으로 제거하지 않고 기존 고객 기록을 보존한다. DB 복원은 별도 승인과 격리 검증을 전제로 한다.

## 운영 보존 및 비용

- SOLQ Sites 버전 28 유지. 운영 홈페이지·관리자 파일·DB·RLS·Edge·Vault 변경 없음.
- GitHub main 유지. 이번 신규 준비 파일은 기존 개발 브랜치에만 저장한다.
- 기존 신청9·계획6·작업7 및 중복 기록 보존. 수락0건은 그대로이며 테스트 수락을 만들지 않았다.
- 실제 Claude/유료 API 호출 0회, 신규 서버·광고·결제 비용 0원.
- 운영 자동 생성 문제가 이미 해결됐다고 보고하지 않는다. 운영 수정은 필수 안전 조건 부족으로 보류다.
