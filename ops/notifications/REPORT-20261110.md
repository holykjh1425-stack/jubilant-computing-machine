## 구현한 개발 후보

구현 커밋: [ef825f97](https://github.com/holykjh1425-stack/jubilant-computing-machine/commit/ef825f97ea2c1d48973afde203595e36b9a6de8c). [실제 CI run 42737253473](https://github.com/holykjh1425-stack/jubilant-computing-machine/actions/runs/42737253473) 성공. 운영 미반영.

1. 신청 저장과 알림 수집·발송 분리. 새 intake는 기존 고객 필드·접수번호·신청 트리거를 보존하고 256비트 토큰의 해시를 저장한다. 신청 트랜잭션은 outbox를 호출하지 않는다. 독립 reconciliation이 활성화 시점 이후 누락 이벤트를 회수한다. 큐 장애 중 신청 저장도 시험했다.
2. 이벤트: 신청 접수, 계좌 보기, 복사 요청, 실제 복사 성공, 관리자의 입금 확인. 계좌 이벤트는 접수번호와 접근 토큰을 함께 검증한다. 각 신청·종류의 최초 이벤트만 기록하여 재전송/연속 클릭 알림을 합친다. 모든 클릭을 계수하는 분석 로그는 아니다. 이전 설치·다른 기기·만료 토큰에는 이벤트 권한이 자동 생기지 않는다.
3. outbox는 이벤트·대상·채널 unique. requested/sending/accepted/retry_wait/failed/uncertain/skipped 상태, 시도 이력, 2분 lease, stale-token 거부, SKIP LOCKED, 일일 시도 상한 50, 최대 3회 재시도와 backoff+jitter를 구현했다. 입력 저장·이벤트 기록·발송 결과를 서로 다른 상태로 취급한다.
4. Gmail OAuth 어댑터와 실행기. 서버용 OAuth refresh token은 환경변수에서만 사용하며 출력하지 않는다. HTTP 성공은 accepted(발송사 접수)이며 수신 완료가 아니다. timeout/5xx/lease 만료는 uncertain으로 보류하고 자동 재전송하지 않는다. Gmail에는 완전한 exactly-once 보장이 없으므로 애매한 건은 운영자가 확인해야 한다. 고객 전화번호를 이메일 주소로 추정하지 않는다.
5. 관리자 snapshot은 실제 Auth user 조회 후 admin_users 확인, 사용자 JWT로 RLS 재확인. 알림·이벤트·시도 각 최근 100건을 textContent로 표시한다. 새 공개 SECURITY DEFINER RPC는 추가하지 않았다. service_role 전용 invoker RPC와 실행 권한을 분리했다.
6. Sites v32용 overlay assembler가 기존 승인·계획·입금 코드와 설정을 보존하면서 8개 파일만 추가/수정한다. 계좌 값은 기존 로컬 원문을 유지하며 새 공개 코드/보고서에 복사하지 않는다. feature flag는 기본 OFF이고 실제 사이트에는 적용하지 않았다.
7. 새 CI는 이 개발 브랜치 push에서만 합성 DB·권한 시험을 수행한다. 운영 자격증명·배포·실제 메시지 발송을 사용하지 않는다.

### 활성화 조사 결과

- Gmail: 최소 scope gmail.send는 sensitive scope이다. Google OAuth 검증/계정 유형별 조건을 확인해야 한다. 외부 앱 Testing 상태의 refresh token은 일반적으로 7일 만료이므로 상시 운용 구성으로 검증해야 한다. 개인 Gmail 일일 500개 초과 등 제한은 별도의 발송 제한이며 API quota가 배달 보장은 아니다. 이메일 주소·비밀번호·refresh token을 채팅/저장소로 보내도록 요구하지 않는다.
- SOLQ 카카오 채널: 현재 Sites 소스 및 관련 연결 메일의 제한 검색에서 채널 운영 증거를 발견하지 못했다. 카카오 관리자센터를 확인한 것은 아니므로 '채널 없음'으로 확정하지 않는다. 비즈니스 채널 인증 여부/관리 권한도 미확인이다.
- 알림톡: 적법하게 수집한 전화번호와 승인된 정보성 템플릿으로 발송한다. 광고 문구를 섞지 않는다. 거래 안내와 광고 수신 동의를 혼동하지 않으며 개인정보 수집 목적·위탁/국외이전·보관 고지를 별도로 점검한다. 현재 사이트 연락처는 이메일이므로 SMS·알림톡에는 전화번호 수집과 고지 변경이 추가로 필요하다.
- 문자: SENS의 사전 등록 발신번호 승인 필요. 사업자 본인 번호에는 사업자등록증·통신서비스 이용증명원 등, 타인/대리 번호에는 명의·위임 서류가 추가된다. 서류 제출·계정 생성은 수행하지 않았다.
- 대체 채널: SENS는 알림톡→SMS 대체발송을 지원하고 승인된 발신번호/프로젝트가 필요하다. 실패 결과가 확정된 뒤에만 별도 이벤트/대상 unique 키로 대체 발송해야 한다. uncertain에 무조건 SMS를 보내지 않는다. 대체 발송 비용·동의 범위를 승인하기 전 OFF로 유지한다. 이번 코드는 이메일만 구현했고 카카오/SMS 어댑터는 활성화하지 않았다.
