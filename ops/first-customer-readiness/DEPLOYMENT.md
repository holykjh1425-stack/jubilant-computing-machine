기존 d6457dd 중복 수정 13개 파일에 견적 연결 6개를 더한 **총19개**를 사용한다. 전체 저장소나 과거 후보 폴더 통째 배포는 금지한다. 예전 manifest의 quote API 제외는 중복 수정만의 범위였으며 이번 통합 적용에서는 quote API가 필요하다.

## 승인 전 필수 조건

1. 실제 관리자 인증을 안전한 조회 전용 경로에서 검증. 구 운영 admin.js를 로그인 시험용으로 열면 자동 생성이 발생할 수 있으므로 사용하지 않는다. 새로운 관리자 계정·JWT 위조·service role 대체 금지.
2. 현재 신청·계획·작업·Auth·ACL·RLS·트리거·함수·cron·배포 설정을 포함한 보호된 일관 백업 및 승인된 비운영 복원 검증. 과거 부분 스냅샷/가상 복원으로 대체 금지.
3. 기존 불필요 권한6개 처리와 새 원장/RPC/트리거 적용의 별도 승인 및 영향 확인. 이 후보는 기존 admin_users RLS나 인증 정책을 변경하지 않는다. 새 원장의 admin SELECT RLS와 좁은 관리자 RPC가 포함되므로 DB 적용 승인 범위를 명시해야 한다.
4. 신규 견적 관련 DB 가드의 실제 다중 세션 잠금·권한 통합이 필요하면 아직 수행하지 않은 부분만 승인된 격리 환경에서 검사. 기존 중복 워커의100연결 PASS는 새 견적 가드 동시성 증명이 아니다.

## 승인 후 적용 순서 (현재 실행 금지)

1. 안전한 조회 전용/유지보수 관리자 패키지 준비. API 쓰기를 하지 않는 확인 경로를 마련하고 기존 SOLQ 설정·CSS·도메인·고객 화면 보존. 제작 제공자는 기존 차단 상태 유지.
2. read-only preflight로 현재8/5/5 및 관계·인덱스·대상 정의를 대조. 숫자 차이가 있으면 정상 신규 접수 여부부터 확인하며 삭제로 맞추지 않는다. quote_acceptances와 production_jobs.quote_acceptance_id 및 기존 approve/guard 함수가 예상과 일치해야 한다. record_quote/RPC/새 원장/트리거 중 일부만 이미 존재하면 자동 덮어쓰기 금지.
3. 보호된 백업 및 DB 적용 승인 후 단일 트랜잭션, lock_timeout3s/statement_timeout30s. applications → ai_work_plans → orchestrator_jobs → production_jobs → solq_quote_acceptances 순서의 잠금 일관성을 검토·확정한다. 다음 원본 SQL을 순서대로 적용하고 검증 후 commit: link-guard.sql → quote-evidence.sql → quote-deposit-guard.sql. 새 원장·함수·트리거 설치만 수행하며 기존 데이터 백필·재연결·삭제는 하지 않는다. 운영의 기존 견적 동의 기록 존재 시 최신 견적 연결을 자동 생성하지 않고 중단/별도 판단.
4. nexus-orchestrator의 index/handler/engine 패키지를 기존 중복 수정 후보로 반영. 정상 서버 워커 보존 및 구 브라우저 등록 요청 차단. solq-quote-evidence의 index/handler를 기존 JWT 전달 설정으로 배포. 새 URL origin/CORS 허용 목록과 실도메인의 대표 주소를 확인. www 등 다른 origin이 필요하면 그 변경만 별도 검증. 서비스 키나 새 관리자 권한으로 우회 금지.
5. manifest의 관리자11개 자산만 원자적 반영. admin.html → admin.js → quote-flow.js → quote-panel.js의 defer 순서 유지. 운영 config와 SDK는 해시·값 확인 후 보존하고 기존 고객페이지·가격·입금 안내는 덮어쓰지 않는다. 해시 기반 버전 URL/캐시 무효화 및 no-store/revalidate 응답 적용을 준비한다.
6. 구 탭 재접속 후 실제 인증·권한·목록·30초 갱신의 업무 쓰기0회, 새 증거 패널 읽기 전용, CSP/캐시·자산해시 확인. 운영에서 임의 가상 고객·동의·입금 증거를 생성하지 않는다. 승인된 별도 환경에서만 양의 쓰기 검증한다.
7. 견적 등록→고객 외부 동의 원본 관리자 대조→동의 증거 등록→30000원 입금 안내→고객 알림→은행 내역 수동 대조→입금 증거·수동 확인→목록 입금 확인 저장→목록 별도 제작 승인→제작 후 잔금 안내. 기본형 총100000원·잔금70000원, 다른 견적 잔금은 총액−30000원. 실제 고객 제작·유료 실행은 이 배포 승인과 별개다.

## 중단 조건

잠금 timeout/중복 인덱스/예상 밖 함수·ACL·정책/잘못된 신청·견적 연결/조회 중 쓰기/무료 워커 오류 증가/승인 없는 제작 요청/실제 인증 실패 중 하나면 다음 단계 중단. 고객 알림은 문의에만 저장되며 입금·승인 조건을 충족하지 않는다.

## 롤백

- SQL 적용 중 실패: 전체 트랜잭션 rollback. 임의 부분 재시도·원장 drop 금지.
- API/자산 실패: 새 증거 쓰기 진입 차단·검증된 조회 전용 유지보수 UI로 전환. 이전 자동 생성 admin.js를 복원하지 않는다. 추가된 데이터 보존형 가드와 원장은 유지.
- 함수/권한 되돌림·가드 제거는 보호된 변경 전 정의·ACL·트리거 연결과 실제 신규 기록을 대조한 별도 승인 필요. 생성된 증거 삭제, 전체 과거DB 복원으로 신규 접수 유실 금지.
- 정상 운영 복구 PASS는 실제 보호 백업·복원 확인 전 주장하지 않는다. 현재는 적용·중단·안전 fallback 절차 확정이며 실제 운영 롤백 실증은 미완료다.
