운영의 문제 원인을 작업 브랜치에서 보완했다. 운영에는 아직 적용하지 않았으므로 운영 중복 위험 해소나 실제 관리자 인증 성공을 주장하지 않는다. 기존 d6457dd에서 재개했고 이미 통과한 동시성·SQL/API·타이머·알림 테스트를 반복하지 않았다.

## 완료

- 관리자 중복 수정안 보존: processNew·plan/assign/tick 자동 호출이 없는 최상위 admin.js/free-workflow.js 사용. 기존 서버 중복 방지 파일과 정상 자동 워커 SQL은 변경하지 않았다. 기존 native100연결·SDK30초 조회·RLS PASS 재사용.
- 기존 최신 견적/입금 후보를 root admin.html에 **quote-flow.js → quote-panel.js** 순서로 연결. 옛 quote-evidence-admin.js는 연결하지 않았다.
- 고객 본인의 외부 견적 동의 원본을 관리자가 대조하는 명시적 등록 경로. 신청ID·최신 견적 참조·버전·금액은 조회한 견적에서 고정하고 클라이언트 입력으로 교체하지 않는다. 발행 전/미래 동의 시각·타 고객 응답·깨진 금액/견적은 차단한다.
- 새/과거 조회 구분, 재조회·로그아웃·탭 숨김·계정 변경 시 기존 양식 무효화. 증거 저장 직전 실제 getUser/membership 재검사. 응답 유실 시 자동 재등록하지 않고 재조회 안내.
- 동의 등록·입금증거 등록·은행 수동 확인은 서로 별도 명령이다. 새 클라이언트에는 제작 승인/실행 명령 자체가 없으며 기존 목록의 수동 상태 저장·별도 승인 RPC와 DB 가드를 유지했다.
- 기본형 총100000원·착수금30000원·잔금70000원을 견적 증거 패널에 표시. 고객 입금 알림은 기존 문의 저장만 수행한다는 직전 격리 검증을 재사용.

## 오류 및 해결

1. **기존 견적 패널 연결 누락:** 최신 root 관리자 HTML에 견적 패널 참조가 없었다. API/SQL/패널 후보는 존재했으므로 재작성하지 않고 공유 관리자 DB와 새 협소 클라이언트로 연결했다.
2. **운영 등록 경로 미반영:** 읽기 전용 조사에서 운영에는 solq_quote_acceptances만 있고 record_quote/원장3개/등록RPC/견적 Edge가 없었다. 따라서 화면 문구만으로 끝나는 상황이었다. 기존 검증 후보19개 묶음과 정확한 적용 순서를 확정했다. 운영 DB·RLS 변경은 금지되어 실제 해결 적용은 보류다.
3. **기존 폼의 낡은 응답/세션 처리 부족:** 다른 조회·로그아웃 후 과거 폼을 사용할 수 있는 경로를 세대값과 사용자 재검증으로 차단했다. 새 테스트로 검증했다.
