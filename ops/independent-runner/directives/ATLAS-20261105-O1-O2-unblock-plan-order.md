## 2. 공통 명령 — 모든 BLOCKED 보고의 12개 필수 필드

앞으로 `BLOCKED`만 제출하고 종료하지 않는다. 각 차단 관문마다 다음을 반드시 기재한다.

1. **Gate ID / 현재 상태 / 기준 시각**: O1, O2 등과 관측 시점.
2. **실제 차단 원인과 증거**: 실패·접근 부재·미실행을 분리하고 로그/문서 위치 기록.
3. **승인권자 및 수행자**: 권한을 부여할 사람과 직접 조작할 사람을 구분.
4. **기존 승인 / 추가 승인 필요 여부**: 승인된 검증 범위를 다시 요청하지 않는다.
5. **Owner의 최소 행동**: 메뉴, 안전한 화면 필드, 금지 버튼, 정확한 전달 형식.
6. **필요 기술 권한·계정·도구·저장소**: 최소 권한과 비밀정보 비공개 원칙.
7. **권한 확보 후 단계별 실제 작업**: 사전조건, 담당 워커, 산출물, 중단 지점.
8. **시간 추정**: 사전조건 충족 후 능동 작업시간/대기시간 각각 최소~최대 범위, 근거 및 불확실성. 근거 없는 숫자를 확정하지 않는다.
9. **비용과 승인 한도**: 기존 자원/추가 비용/상한 미확정. 새 유료 리소스 한도 0원.
10. **정량적 PASS / FAIL / 재시도 조건**: 확인할 실제 증거, 실패 시 안전 중단, 다음 시도 트리거.
11. **대체 합법 경로**: Owner 직접 조작·공식 지원·기존 로컬 자원. 인증 우회/비밀번호 재설정/운영 설정 변경은 금지.
12. **다음 Gate 및 전체 일정 영향**: 선행조건·병렬 가능 작업·임계 경로·잔여 위험.

불명 사항은 `미확인`으로 두되 **확인할 주체와 방법**을 붙인다. `예정`, `추후 확인`만으로 끝내지 않는다.

## 3. Gate-O1 — Owner 백업 접근 해제 계획 (GUARD 책임)

**현재:** BLOCKED. 계정 권한 승인 자체보다 **실제 Owner 세션/보호된 Windows 실행 경로 부재**가 차단 원인.

- **승인권자:** Supabase 프로젝트 Owner(사용자). Windows 보호 저장소·로컬 실행 권한은 해당 PC 관리자/Owner. 제공자 측 백업 이슈 해결은 Supabase 지원팀.
- **이미 승인됨:** 기존 Pro 백업 화면 읽기, 안전한 검증 범위. 추가 승인이 필요한 것은 *새로운 과금 또는 승인 대상 밖의 데이터 반출* 등 구체 작업뿐.
- **Owner 최소 행동:** 기존 Owner 계정으로 Supabase 프로젝트 `elfacqmvygnwjlklqhiz`의 `Database → Backups`를 열고 **최신 복구점 날짜·시각·시간대, 백업 유형, 완료/오류 상태, 다운로드 옵션 유무**만 확인해 ATLAS에 전달. 메뉴명이 다르면 실제 UI를 따라 읽기 전용으로 확인한다. `Restore`/`Clone`/`Reset`/`Upgrade`는 클릭하지 않는다. 비밀번호·토큰·키·연결 문자열·고객 정보는 전달하지 않는다.
- **다음 접근 조건:** 안전하게 연결 가능한 기존 브라우저 세션 또는 Owner가 직접 전달한 비밀 없는 화면 정보; 기존 Windows 보호 실행 경로; 유효한 공식 DB 읽기 인증; TLS verify-full/CA; 암호화 공개키 지문·수신자 확인; 비동기화 및 ACL이 검증된 저장 위치; 복구키 관리자.
- **권한 확보 후 수행:** (1) Pro 복구점/종류 및 다운로드 가능성 분류, (2) DB 논리 덤프/제공자 공식 보호 반출 가능성 판정, (3) 전체 범위(DB/Auth/Storage/Edge/Vault/SMTP/OAuth) 누락 확인, (4) 일관된 백업 시점과 키·보관·비용 확정, (5) 허용된 범위에서만 암호화 백업·SHA-256 무결성 증거 확보.
- **PASS 구분:** `O1-A 조회 접근 PASS`는 실제 복구점 상태·범위·다운로드 가능 여부를 확인한 증거가 있을 때, `O1-B 백업 실행 준비 PASS`는 인증·보관·암호화·복구책임·비용·범위가 모두 확인됐을 때만. 백업 파일 실제 생성은 별도 `B1 백업 완료` 관문이다. **대시보드 조회만으로 전체 O1/B1 완료를 주장하지 않는다.**
- **FAIL/BLOCKED:** 복구점 부재/실패, 실제 보관 위치·키·범위 미정, 공식 접근 미확보, 자격증명 노출 위험, 지원하지 않는 다운로드 유형, 유료 기능 요구, 스냅샷 일관성 불가. 원인별로 나누어 표시.
- **대체 경로:** Owner가 직접 화면 정보 전달 → 기존 보호 Windows 기반 TLS 검증 읽기 덤프 → 스트리밍 암호화; 필요시 공급자 공식 지원. 인증 우회, 계정 재설정, 비밀키 채팅 전송 없음.
- **시간 산정:** 다음 관측 단계인 UI 조회는 **Owner 실제 조작 5~10분(계획치, 미측정)**. O1-A 확인은 회신 및 UI 접근 후 **약 10~20분의 검토 작업(초기 추정, 미측정)**. O1-B는 인증·저장소·범위·백업 유형 확인 이후 재추정; **현재 확정 불가**. 실제 데이터 백업 소요시간은 데이터/egress/접속 속도 미확인으로 별도 계측해야 한다.
- **산출물:** 표 형태 O1 해제 계획, 복구점 조회 증거, 권한/저장소 체크리스트, 필요시 정확히 **한 가지 Owner 행동 요청**.

## 4. Gate-O2 — 안전한 격리 복원 해제 계획 (CORE 책임, GUARD 검증)

**현재:** BLOCKED. 기존 로컬 PG17/Supabase 복원 대상의 실재·접근성과 운영 분리·외부 송신 차단이 현 세션에서 확인되지 않았다.

- **승인권자:** 로컬 환경/스토리지 관리자 또는 Owner. 신규 유료 프로젝트/외부 고객 데이터 반출 시 **별도 Owner 명시적 승인**, FIN 비용 선검토.
- **필요 환경:** 기존 보호된 비운영 PostgreSQL 17 및 Auth/Edge 검증 환경을 우선 사용. 운영과 다른 호스트·DB 주소·계정·볼륨·네트워크·프로젝트 식별자; 보호된 충분한 저장 공간; 백업 복호화 경로; 서비스 기능 검증 수단.
- **계정·저장소:** 운영 관리자와 분리된 최소 권한 복원 계정, 보호된 암호화 백업 입력, 분리된 복원 대상 저장소 및 비밀 없는 진단 로그.
- **복원 *전* 필수 통제:** 외부 SMTP·webhook·cron/pg_cron·pg_net·Edge 호출·유료 AI API·결제·고객 알림 차단. 필요시 네트워크 egress 거부 및 합성 비밀정보로 대체. 공급자 Clone은 외부 작업이 즉시 실행될 위험이 있으므로 사전 검증/별도 승인 없이 사용 금지.
- **실행 순서:** (1) 대상 식별/운영 비연결 증명, (2) 외부 송신 차단 증명, (3) 안전한 백업 복호화/복원, (4) 테이블·컬럼·함수·트리거·인덱스·RLS·권한·데이터 내용·시퀀스 비교, (5) Auth/Edge 최소 생존 기능 확인, (6) RPO·RTO 실측, (7) 복원 환경 폐기/보존 승인과 접근 회수.
- **PASS 구분:** `O2-A 격리 안전성 PASS`는 서로 다른 연결 정보/저장소와 외부 송신 차단이 **복원 전** 확인될 때만. `O2-B 실제 복원 PASS`는 B1 완료 백업으로 실제 복원 + 정량/내용 비교가 일치(또는 사전 승인된 차이)하고 필수 기능 PASS 시. RPO/RTO는 별도 수치 기록.
- **FAIL/BLOCKED:** 분리 검증 실패, 송신 경로 미차단, 보호 공간 부족, 복구키 부재, 복원 호환성 실패, 고객 메시지 발송 가능성, 예상치 못한 추가 과금. 즉시 중단·격리 유지·실패 증거 보존.
- **대체 경로:** 기존 로컬 복원 대상 관리자 직접 실행 및 비밀 없는 결과 전달; 공급자 공식 복제는 안전·가격·개인정보 조건 확인 후 별도 승인 시에만.
- **시간 산정:** 기존 자원 확인과 egress 차단 준비는 **약 15~30분 사전 점검(계획치, 미측정)**. 실제 복원시간과 기능 검증시간은 백업 크기·복호화 속도·가용 자원·Auth/Edge 구성 여부를 모르는 상태에서 **수치 확정 불가**. CORE는 대역폭·복원 대상 사양·백업 용량을 확인한 후 **최소~최대 범위 및 산정식** 제출. 임의로 `O2 PASS N시간` 보장하지 않는다.
- **산출물:** O2 환경 격리·무송신 체크리스트, 검증 방법, 담당자/승인자, 비용/시간 추정, 단계별 PASS/FAIL, 실패 시 안전 종료 조건.

## 5. 전체 일정 및 임계 경로 (GUARD + CORE + FIN)

워크플로 선후관계:
`Owner 백업 UI 조회(O1-A) → 백업 권한·암호화 저장소 준비(O1-B) → 실제 암호화 백업(B1) → 독립 복원 안전성 확인(O2-A) → 실제 복원/무결성(O2-B) → RPO/RTO 실측 → 최종 보안·PC/Android/iOS·롤백 → ATLAS 승인 패키지`.

가능한 병렬 업무: O1 중 기존 O2 환경 사전 점검(읽기 전용), SENTINEL 보안 위험표/수정 후보 확인, CORE 회귀 테스트 계획, FIN 자원·상한 검토. 운영 변경·실제 고객 데이터 테스트는 하지 않는다.

**시간 보고 의무:** 각 활동에 `선행조건 / 담당자 / 능동 작업시간 최소~최대 / 외부 대기시간 / 추정 근거 / 관측 또는 계획 / 비용 / 다음 Gate` 열을 둔다. Owner 조작·지원팀 응답 대기·복원 실제 수행 시간을 분리. 총 예상 기간은 임계 경로 합계로 표현하되, **핵심 변수 미확인 시 전체 완료 시간을 숫자로 단정하지 않는다.** 각 단계의 수치를 확보할 때마다 임계 경로를 갱신한다.

**최초 일정 예시(기존 2026-11-05 보고서의 계획치 재사용; 실제 관측 아님):**
- Owner 백업 UI 확인: 약 5~10분 (Owner 직접 조작)
- O1-A 조회 내용 해석 및 경로 판정: 약 10~20분 (작업 추정)
- O1-B 보호 접근/키/저장소 확보: 미확인(접근 조건 미비)
- O2-A 기존 로컬 복원 대상 점검: 약 15~30분 (작업 추정)
- B1 전체 암호화 백업: 용량·대역폭 미확인 → 산정 보류
- O2-B 실제 복원 및 검증: 용량·환경 미확인 → 산정 보류
- RPO/RTO 측정: 복원에 포함해 실측; 사전 확정 불가
- 보안·실기기 회귀·롤백: 접근/수정 승인·기기 가용성 미확인 → 산정 보류

상기 수치는 **서비스 전체 완료 예상 시간이나 SLA가 아니다**.

## 6. 워커 책임 배분 및 보고 지침

- **GUARD (주관):** O1 해제 계획, B1 백업·O2-B 독립 검증, 복원 무결성/RPO/RTO, 최종 Gate 판정. 구체 접근 불가면 해제 계획서 제출.
- **CORE:** O2 환경 실제 분리/송신 차단 방법 및 단계별 시간 산식, PC/Android/iOS 회귀 준비, 운영 변경·롤백 목록. 환경에 대한 접근이 없다면 Owner 1회 조작 안내.
- **AUTO:** 복원 후 실제 고객 데이터에 손대지 않는 최소 업무 검증 항목·합성 데이터 경계, 예상 검증시간 산정 근거.
- **SENTINEL:** 7개 기존 Advisor 경고·기본 ACL·Security Definer·`admin_users`·Password Protection 잔여 위험표와 해결 조건. 운영 보안 변경 없이 상태 보고.
- **FIN:** 기존 Pro/로컬 자원 비용 제약, 별도 결제·외부 저장 필요 시 비용·과금 조건·상한·Owner 승인표. 신규 유료 자원 한도 0원 유지.
- **ATLAS:** O1/O2 차단 해제 계획을 통합하여 Owner의 최소 한 가지 다음 행동과 **완료시간 전망의 불확실성**을 명시한 최종 의사결정 보고서 제출.

## 8. 엄격한 금지 및 종결 기준

- 위 지시는 **차단 해제 계획의 문서화와 안전한 조회/준비**를 지시한다. 원격 Owner 세션·Windows 저장소·비밀키 접근 권한을 창설하지 않는다.
- 비밀번호·개인키·API 키·고객 행을 채팅, 공개 GitHub, Actions 산출물/로그에 남기지 않는다.
- 운영 DB/RLS/Auth/SSL/Vault/Edge/사이트/설정 변경, main 병합, 고객 통보, 유료 API 호출, 신규 유료 자원 생성은 별도 승인 전 금지한다.
- 권한 미확보 상태에서 **백업 성공, 격리 복원 성공, RPO/RTO 수치**를 작성하지 않는다.
- 기존 51 PASS를 재실행하지 않는다. 새로운 차단 사유가 발견되면 증거와 해제 조건을 기록한다.

**운영 판정은 NO-GO 유지. 이 지시서의 완료 기준은 모든 Gate를 허위 PASS로 만드는 것이 아니라 O1·O2별 실행 가능한 해제 계획·책임자·시간 산정 근거·최소 Owner 행동을 빠짐없이 제출하는 것이다.**
