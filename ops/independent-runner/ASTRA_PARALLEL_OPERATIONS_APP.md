# ASTRA 병행 실행 계획 — SOLQ 운영 + 앱 MVP (2026-11-02)

## 책임 체계
ASTRA: 총괄 의사결정 준비, 우선순위, 지출 사전심사, 검증 증거 확인, 결과 보고. ATLAS: 공통 장부·자동화 조정. CORE: 웹/앱 UI와 신청 흐름. AUTO: 작업 흐름·원자적 저장 후보. GUARD: 테스트/릴리스 게이트. SENTINEL: 개인정보·보안. FIN: 비용·수익 검토. GROW: 고객 전환.

## 두 트랙 분리
**트랙 A — 운영 안전성(P0)**: 기존 운영 고객 데이터·main·배포 보존. 관리자 인증, 원자적 저장, 전체 암호화 백업, 격리 복원, 보안 위험 검토. 모든 필수 검증과 별도 승인 전 배포 NO-GO.

**트랙 B — 신규 앱 후보(P1)**: 기존 SOLQ 고객 접수 웹과 호환되는 모바일 우선 앱 MVP를 *임시 가정*으로 설계. 사용자 최종 플랫폼(iOS/Android/PWA)과 실제 앱 목적은 확정 전. 격리 개발 브랜치에서만 화면·테스트·모의 데이터 사용.
- 화면 후보: 홈/서비스, 무료 6단계 계획 신청, 개인정보 동의, 접수번호 확인, 진행 상태 조회, 관리자 로그인/검토(실제 인증 통합은 별도 검증).
- 고객 실자료를 개발 환경으로 복사하지 않음.
- 실제 입금/제작 승인/유료 API는 개발 앱에서 자동으로 실행하지 않음.
- 기존 SOLQ 3중 승인(관리자 인증+입금 확인+별도 제작 승인) 유지.
- 앱 스토어 등록·유료 호스팅·운영 배포는 별도 승인 필요.

## 충돌 방지
- CORE는 앱 UI 후보만 소유; 운영 DB/Edge 관련 변경은 AUTO의 별도 후보와 GUARD 검토 후.
- 동일 파일·브랜치 동시 쓰기 금지; 작업 ID·기준 커밋·검토자·증거 기록.
- 원자적 잠금 E2E PASS 전에는 자동 병렬 쓰기 금지.
- 이전 63 PASS 반복 금지. 완료되지 않은 검증을 PASS로 표시 금지.

## 비용 원장 기준
- 승인된 무과금 준비 작업: 신규 현금 지출 목표 0원. 이는 실제 계정 청구액 확인을 대신하지 않음.
- 비용 보고: 예상비용, 승인한도, 실제 청구액(증빙 확인 시), 미확인액, 누적액, 추가 승인 필요.
- Claude/서버/광고/도메인/앱스토어/계약/세금 신고/자금 이체는 개별 승인 없이는 금지.
- 교회·비영리 자금과 SOLQ 사업 자금은 철저히 분리.

## 완료 기준
1. 자동 실행 엔진 CI 로그 및 산출물 PASS.
2. 작업 소유권/중복 방지와 안전 복구 검증 PASS.
3. 앱 화면·입력·동의·접수번호 모의 E2E PASS, PC/모바일 레이아웃 검사 PASS.
4. 운영 필수 인증·원자적 저장·전체 백업·격리 복원 PASS 전에는 실제 배포 금지.
5. 고객 유입·견적·유료 계약은 실제 증거로만 보고.
6. ASTRA 최종 보고: 완료/미완료/차단, 증거 URL, 비용, 위험, 다음 단계, 별도 승인 요청.

## 현 상태
병행 작업 지시와 안전 범위 문서화. 앱 개발 구현 및 실행 테스트는 아직 미완료. ChatGPT 채팅 간 직접 자동 소집 기능 미구현.
