## 9. 파일·적용 순서·복구

- candidates/cost-control/engine.mjs: 모의 배정·캐시·단일 프로세스 참조 원장. 운영 원장 대체 금지.
- budget-candidate.sql: 신규 비공개 스키마·정책·승인·예약·정산 함수 후보. 기존 테이블/고객/RLS/Vault 변경 없음. 운영 미적용.
- edge-boundary.mjs: 실호출 불가 경계 후보. 기존 Edge 변경 없음. 실제 서버용 원장/캐시 어댑터는 아직 없다.
- admin-preview.html: 자체 포함 합성 화면, 네트워크·로그인·저장·실행 없음. 실제 승인 버튼 비활성. 공개 배포 안 함.
- rollback-candidate.sql: 신규 함수의 실행 권한만 회수하고 건강 상태 차단. 운영 미실행·격리 SQL 실행 미검증. 과거 원장이나 고객 데이터를 삭제하지 않음.
- tests/cost-control: 새 JS/네이티브/UI 검사, 합성 비교·재현 코드·증거.

운영 적용 순서는 (1) 기존 전체 백업/보호된 복원 준비 및 별도 승인 (2) 신규 SQL 승인·보안 검토·운영 실제 관리자 인증 매핑 (3) 실호출 비활성 서버 어댑터·영속 결과 캐시·실제 토큰/원장 대사 구현 및 통합 검증 (4) 조회 전용 관리자 UI 연결 (5) 별도 승인하에 키/제공자 계정·모델·제공자 지출 제한 확인 (6) 작업별 실제 유료 실행 승인이다. 각 단계는 현재 허용된 실행을 뜻하지 않는다. 이 후보는 모든 유료 실행을 비활성으로 유지하며 SQL의 live_enabled=true도 제약으로 거부한다. 활성화는 별도 코드·안전 검토가 필요한 변경이다.

장애 시 새 진입점/워커부터 중지하고 예약·감사 원장을 보존한다. rollback 후보는 새 스키마 함수만 차단한다. 기존 고객 흐름·기존 Edge/무료 승인 RPC·과거 중복 기록을 정리하거나 되돌리지 않는다. 기존 백업/TLS/격리 복원 차단 조건은 해결됐다고 간주하지 않는다.

## 10. 남은 위험과 승인

키 유효성·발급 조직, 실제 Work→Claude 연계, 영속 원장/캐시 서버 어댑터, 실제 tokenizer, 운영 사용량 대사·SQL 장애 복구, 실제 관리자 화면/PC/실기기 모바일, 제공자 제한·실제 추론 성능·의미 품질·Work 사용량 절감이 미검증이다. 운영 적용은 보류한다. 지금 유료 API 호출/결제/새 키/운영 DB/main/배포 승인을 요청하지 않는다. 다음 독립 개발은 실제 호출 없는 서버 어댑터와 보호된 통합 검증이며, 운영 변경은 범위·위험·백업·복구를 갖춘 별도 승인 후만 가능하다.
