준비만 완료. 계정 설정/키/비밀 저장소 변경·실제 제공자 호출·결제·배포는 실행하지 않았다. 기존33 PASS(7f03c92)와 가격 검토를 재사용하며 재검증하지 않았다. 이번에는 신규 준비 경계의 합성 검사3개만 실행했다.

## 실제 계정 확인 범위

사용자가 확인한 계정·GGWELL's Individual Org·Default·잔액US$5·키0개를 마지막 관측으로 수용한다. 이 보고서는 개인 이메일을 공개 저장소에 다시 기록하지 않는다. 현재 Work에서 접근 가능한 Chrome 탭은0개이며 사용자의 PC Console 세션을 열람할 수 없다. 로그아웃·새 로그인·인증 재요청은 하지 않았다.

따라서 현재 조직 ID·역할·현재 잔액·키 목록·SOLQ-TEST 존재·생성 권한·실제 월 지출 한도·자동충전·RPM/ITPM/OTPM·키별 권한/만료 설정은 미확인이다. Supabase Owner라는 사실은 Claude Organization Admin 역할의 증명이 아니다. 마지막 표시값을 이번 실시간 검사 결과로 바꾸지 않는다. 이 계정은 사용자가 지정한 SOLQ 공식 API **후보**이며 기존 운영 Vault 키의 발급 조직과 같다고 단정하지 않는다.

## 공식적으로 지원되는 설정과 제안값

공식 Workspace 문서상 Organization Admin은 전용 Workspace를 생성할 수 있다. Workspace 키는 해당 Workspace에 연결되며 이동할 수 없다. Default에는 별도 월 지출 한도를 지정할 수 없고, 별도 Workspace 한도는 조직 한도보다 낮아야 한다. 실제 계정의 역할·입력 가능 금액·한도 옵션은 화면 접근 전 확정하지 않는다.

제안: 조직 월US$5 이하, SOLQ-TEST 월US$1. 조직에 더 낮은 한도가 이미 있으면 올리지 않는다. 실제 UI가 제안값을 허용하지 않으면 지원되는 더 낮은 금액을 확인하거나 준비를 보류한다. 조직 한도 변경은 Default/다른 사용처에도 영향을 줄 수 있으므로 별도 승인 범위다. 잔액US$5는 지출 한도 설정이나 사용 승인의 증명이 아니다. 월 한도·잔액·사용량·내부 일 한도는 별개다.

Billing에서 자동충전 상태를 확인해야 하며, 현재 ON/OFF는 미확인이다. OFF 확인 전 시험하지 않는다. 자동충전 활성화·추가 구매·결제수단 추가·조직 한도 증액은 제안하지 않는다. 이번에는 OFF로 바꾸는 설정 변경도 하지 않았다.

요청 속도: 실제 조직/Workspace RPM·입력 토큰/분·출력 토큰/분을 Limits 화면에서 기록한 뒤 그 이하로 사용한다. 초기 내부 기준은 동시1·분당1회·승인된 전체1회·자동 재시도0이며, 이는 제공자 설정 완료라는 뜻이 아니다. 실제 제공자 하한/세부 설정과 계정 모델 이용 권한은 미확인이다.

## 기존 운영 키와의 분리

- 기존 Vault nexus_labs_claude_api_key 및 ANTHROPIC_API_KEY는 이름·값·참조·권한·기존 Edge를 모두 유지한다. 기존 키로 테스트하거나 실패 시 대체하지 않는다.
- 새 키 발급은 미실행이며 별도 승인이 필요하다. 승인 후에만 SOLQ-TEST를 명시적으로 선택하고 일반 Workspace 범위 테스트 키를1개 발급한다. Console 관리용 Admin 키나 조직 전체에 넓은 권한을 가진 키를 기본으로 사용하지 않는다.
- 별도 이름 예: solq-test-20261028. 실제 UI가 키별 Messages 전용 권한 또는 만료 시각을 지원하는지는 미확인이다. Workspace 범위를 세밀한 API 권한과 동일하게 취급하지 않는다. 서버에서도 허용 모델·단일 합성 텍스트·토큰·호출·비용 상한을 제한해야 한다.
- 가능한 경우 짧은 제공자 측 만료를 사용한다. 내부 검토 기한은 발급 후24시간으로 제안하되, 내부 차단만으로 외부에서 유출 키가 만료되는 것은 아니다. 제공자 만료가 없으면 사용자 승인된 시험 종료 후 테스트 키 비활성화 절차가 별도로 필요하다. 자동 비활성화/삭제는 이번에 실행하지 않았다.

## 테스트용 비밀 저장소와 어댑터

실제 별도 비밀 저장소나 비운영 서버의 존재·보호 상태는 확인되지 않았다. 따라서 **실물 저장소 준비는 미완료**다. 운영 Supabase Vault/Edge secrets에 새 항목을 만들지 않았으며 Windows Credential Manager·환경 변수·클라우드 설정도 변경하지 않았다.

준비한 것은 메타데이터 계약과 실행 불가 경계다.

- 논리 참조: solq-test/anthropic-api-key. 추후 비운영 런타임 주입 이름이 필요하면 SOLQ_TEST_ANTHROPIC_API_KEY를 사용하되 기존 이름과 분리한다.
- 대상은 기존의 승인된 비운영 런타임 비밀 저장소여야 한다. 신규 서버/계정을 만들거나 운영 Vault를 임시 테스트 저장소로 사용하지 않는다. 보호된 대상이 확인되기 전 키를 발급해 둘 필요가 없다.
- 사용자/승인된 관리자만 공식 Console에서 생성된 값을 해당 보호 입력 화면에 직접 보관한다. 채팅·GitHub·소스·HTML·CLI 인수·일반 설정 파일·로그에 키를 넣지 않는다. 최소 런타임만 읽기 가능하고 Work/클라이언트에서 가져오지 않는다.
- 향후 SecretProvider 인터페이스는 승인된 테스트 참조만 해석하고 누락 시 실패해야 한다. 기존 운영 키나 기본 ANTHROPIC_API_KEY로의 fallback은 금지한다. 실제 비밀 조회 구현과 HTTP 전송 구현은 아직 없다.
- test-profile.example.json은 비밀 없는 준비 프로필이며 조직/Workspace ID는null이다. 검사 플래그는 확인되지 않았으므로 false로 유지한다. 직접 값을 true로 바꾸는 것은 인증/설정 증명이 아니다.
- test-adapter-preparation.mjs는 프로필만 검사한다. 환경/비밀 저장소를 읽지 않고 네트워크·SDK를 사용하지 않는다. 모든 항목을 합성 값으로 충족시켜도 readyToExecute=false, transportImplemented=false이며 executeTest는 항상 차단된다. 준비용 플래그로 실제 실행을 해제할 수 없다.

6. 단일 승인/예약 ID로1회만 실행하고 요청 ID·조직/Workspace 식별 메타데이터·사용 토큰·결과 구조·비용 계산을 대사한다. 키·Authorization·고객 정보·원문 오류/응답 전체는 기록하지 않는다. 통신 시간 초과나 사용량 불명확은 예약 유지·재시도 중단이다. 전송 취소가 제공자 과금 취소를 보장하지 않는다.
7. 결과와 제공자 사용량을 확인한 뒤 종료한다. 계획된 테스트 키의 비활성화/만료는 해당 범위 승인 후 처리한다. 기존 운영 키에는 손대지 않는다.
