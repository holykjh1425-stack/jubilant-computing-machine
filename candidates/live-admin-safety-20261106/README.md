# 버전28 관리자 자동 생성 제거 후보

기준은 Sites 배포 원본 `ab4d34c830669e69b57f0689588eb6a24b41f91e`이다. GitHub 관리자 파일을 운영 원본으로 가정하지 않았다.

운영 적용 후보는 `dist/admin.html`, `dist/admin.js`, `dist/free-workflow.js`, `dist/plan-view.js` **4개만**이다. `qa*`, `responsive.html`, 미리보기 index, 설정, fixture는 배포 대상이 아니다. 스타일과 메인 신청 화면은 변경하지 않는다.

- 기존 검증된 조회 전용 free-workflow와 plan-view를 재사용한다.
- 로그인·목록 표시·30초 타이머의 plan/assign 호출을 제거한다.
- 서버 cron의 무료6단계 자동 처리는 유지한다. 관리자 화면은 이미 저장된 계획·연결 작업을 조회한다.
- 중복 작업 또는 다른 고객/계획 연결을 발견하면 오류를 표시하고 생성하지 않는다.
- 입금 확인과 별도 제작 승인 코드 및 고객지원·일반 상태 저장 코드는 버전28 원문 그대로 유지한다.
- 현재 운영 미적용. 실제 관리자 인증·최종 격리 통합·백업/롤백 관문 통과 전 배포하지 않는다.

## 검증
`results.json`에 새 변경 부분만 기록했다. 합성 관리자 fixture는 실제 인증이 아니며 CSP connect-src none 및 실패하는 쓰기 스텁을 사용한다. 기존51 PASS는 재실행하지 않았다.

`assemble.py`는 기존 로컬 Sites 저장소 객체에서 정확한 배포 커밋을 읽으며, 나머지 관리자 상태 저장 코드가 원문과 동일한지 assert한다. `prepare-preview.py`는 합성 미리보기만 만든다. 이 과정은 운영 서버/DB에 쓰지 않는다.

## 적용/롤백 준비
1. 현재 Sites 버전·소스가 여전히28/기준커밋인지 재확인한다. 달라졌으면 변경을 재대조한다.
2. 4개 후보 파일의 SHA-256과 승인된 변경 목록을 확인한다.
3. 보호된 실제 인증 환경에서 관리자 조회·권한·최신 DB/Edge 연결을 검증한다. 운영 고객 상태를 시험 변경하지 않는다.
4. 전체 백업·복원·보안·회귀 및 롤백의 미완료 승인 관문을 종결한다.
5. 검증된 범위의 배포 승인 조건이 충족된 후에만 Sites 소스의 해당4개 파일을 반영한다. 홈페이지 전체를 GitHub main으로 교체하지 않는다.
6. 적용 실패 시 기존 저장 버전28로 복구한다. 이 문서는 롤백 실행 PASS 증거가 아니다. 운영 DB 변경은 이 후보에 포함되지 않는다.
