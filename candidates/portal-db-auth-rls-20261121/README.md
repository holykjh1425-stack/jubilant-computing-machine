# SOLQ 포털 DB·Auth·RLS 통합 준비 후보

DEV-02는 PostgreSQL 17.11 통합의 실행 관문과 검증 자산을 추가한다. DEV-01의 포털 11개 파일과 모의 공급자는 그대로 사용한다. 이 디렉터리의 어댑터는 기본 OFF이며, 켤 수 있는 실행 모드는 인프로세스 합성 `fixture`뿐이다. 전송 코드, 자격증명, 운영 URL을 포함하지 않는다. 운영 NO-GO.

| 파일 | 범위 |
| --- | --- |
| `review/01_schema.REVIEW_ONLY.sql` | 신청·동의·업무 상태, 트랜잭션 RPC, 합성 Auth 세션·역할 확인, RLS 및 후보 Storage |
| `review/02_rollback.REVIEW_ONLY.sql` | 비어 있고 정지된 합성 후보만 대상으로 한 테이블·함수·Storage 정책 원복 |
| `adapter.mjs` | 기본 OFF, 승인 후보 식별자 고정, Auth·PostgREST·트랜잭션 합성 인터페이스 |
| `verify/` | 독립된 합성 서비스와 역할·트랜잭션 시험 및 SQL 어휘·정책 구조 점검 |
| `TEST-PLAN.md` | 실제 독립 환경의 관문, 시험 행렬, 증거·중단·원복 절차 |

## 검토 계약

- 신청은 Auth가 검증한 합성 고객만 제출한다. 비로그인 사용자는 DEV-01의 로컬 상담 기능을 사용할 수 있다. 저장 원본은 업무 상태에서 분리한다. 고객·요청 UUID의 고유 제약과 접수번호의 별도 고유 제약을 적용하고 개인정보·국외 이전 동의의 개별 버전·SHA-256·서버 UTC를 같은 트랜잭션에 넣는다.
- 같은 고객·키·원본이면 이전 행을 다시 읽는다. 본문 변화는 충돌이고, 번호 고유 제약 충돌만 최대 4회 다시 할당한다. DB 원본과 두 동의 원장이 일치할 때만 저장 결과를 반환한다. PostgreSQL의 `jsonb::text` 기반 서버 지문은 DEV-01 클라이언트의 JSON 바이트 지문과 같은 값으로 간주하지 않는다. 실제 연동 시 서버 정규화 규격과 커밋 증거를 별도로 연결한다.
- RPC 역할은 비로그인·비슈퍼유저·BYPASSRLS 없음으로 별도 준비해야 한다. 신청·동의·상태에는 강제 RLS를 적용한다. 클라이언트는 보호 테이블에 직접 권한이 없다. Auth의 세션 및 사용자 식별자를 승인한 합성 세션 목록에 대조하고 만료·회수를 매 요청에서 검증한다. 승인된 테스트 도구만 세션 목록·관리자·고지 fixture를 준비한다. 이 파일에는 실제 Auth 호출이나 시드가 없다.
- 견적 동의, 착수금 30,000원 모의 확인, 별도 제작 승인은 같은 견적 버전에 귀속된다. 실행 관문은 모든 분기에서 `allowed=false`를 반환한다. 승인된 고지 원문이나 법적 문구를 이 시험 자료로 대체하지 않는다.
- Storage에서 전용 비공개 버킷은 소유자 또는 현재 스태프만 읽도록 검토했다. 클라이언트 객체 쓰기는 차단한다. DB 수준의 역할·JWT·RLS·Storage 실제 동작은 검증 대기다.

## 실행 및 판정

```text
node --test verify/fixture.test.mjs verify/static.test.mjs
```

SQL 검사는 어휘 균형과 승인 관문·권한 구조 점검이다. PostgreSQL 파서, 실제 DDL·함수 컴파일, 정책 평가 및 REST 커밋 가시성은 미실행으로 기록한다. 재기동 시험은 직렬화한 **합성 스냅샷을 새 모형에 적재하는 시험**이다. Windows 서비스 재기동이나 디스크 내구성을 판정하지 않는다. 

실제 실행 승인 전에는 두 SQL 파일이 `ROLLBACK`으로 종료되는 검토본 상태를 유지한다. 운영 경로의 변경·구 등록 회수, 실제 고객 데이터를 사용한 복원, 최초 유료 제작 실행은 별도 운영 전환 범위다.
