## 순서와 중단 기준

1. 사전 관문을 승인 증거와 대조하고 정확한 로컬 대상·역할·파일 해시·포트를 기록한다. 다른 기존 서비스나 운영 접근 가능성이 보이면 시작하지 않는다. 실제 명령은 승인된 비운영 대상에 귀속된 실행안에서만 확정한다.
2. 합성 대상의 접근·DB 기동 승인 후 한정된 계정으로 환경을 확인한다. 별도 승인 아래 리뷰 파일을 실제 실행 후보로 식별하고 파서/함수를 검증한다. 검토본은 자체 `ROLLBACK`으로 종료된다. 실제 커밋을 만드는 버전은 별도 검토와 해시 및 승인 대상이다.
3. 합성 Auth, PostgREST 및 Storage를 동일 격리 대상에 연결해 표의 권한과 상태를 시험한다. 로그에는 시험 ID·역할·시각·허용/거부 상태·지문만 남긴다. 접속 문자열, 실제 계정 및 운영 데이터는 기록하지 않는다.
4. 서비스·포트·PID 이탈, 비인가 접근, 기존 자산 변경, 동의/원본/커밋 불일치 또는 외부 통신이 발견되면 중단한다. 인증 정보를 새로 요구하거나 권한을 확대해 재시도하지 않는다.
5. 신원이 검증된 합성 대상만 승인 방식으로 종료하고 사전·사후 증거를 보존한다. 승인된 fixture 정리는 별도 작업으로 기록한다. 원복 SQL은 정지된 합성 대상에서 서명된 빈 대상 조건 아래 후보 객체만 제한적으로 제거하도록 설계됐다. 데이터가 남아 있거나 종속성이 다르면 중단하며 원래 운영·DEV-01 파일에는 변경을 적용하지 않는다.
