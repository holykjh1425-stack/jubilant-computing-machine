## 확보 방식
공식CLI2.122.0 고정, 공식 GitHub release asset SHA256=59ed066847b98d7461c60e9109d40cab6b9756177ce06ebb05b51338519f5136 검증. 사용 전 --help로 init/start/status/stop/functions serve 옵션 확인.
별도 임시 디렉터리에 unlinked local project_id=solq-local-ci. hosted project 생성·로그인·link·deploy 없음. 기존 공개 저장소의 표준 GitHub runner에서 재현하는 무료 로컬 검증 구성으로, 신규 유료 인프라가 아니다.
Docker network internal=true, 기본 host binding127.0.0.1. 실행 후 모든 스택 컨테이너가 해당 네트워크 하나만 사용하고 공개 포트가 loopback에만 바인딩되는지 검사한다. 외부로 라우팅되는 컨테이너 네트워크나 wildcard 포트면 인증/신청 테스트 전에 중단한다. CLI/이미지 다운로드는 runner가 공식 배포처에서 수행한다.
Start/status 출력은 메모리 캡처하며 로컬키/세션/비밀번호/사용자 원문응답을 로그·결과파일·GitHub에 기록하지 않는다. 기존 운영키·Windows Credential Manager·Vault는 읽지 않는다. Supabase 로컬 스택이 만든 일회성 로컬 anon키와 랜덤 합성계정 비밀번호만 실행 중 사용한다. Edge는 local anon키와 전달받은 실제 로컬 사용자JWT로 RLS를 유지하며 service_role을 사용하지 않는다.
합성계정2개는 실제 로컬 GoTrue signup/password login으로 생성/인증하며 외부 이메일·실제사용자·OAuth와 무관하다. 관리자멤버십은 새 로컬 DB fixture에만 설정한다. user_metadata에 admin표시를 넣은 비관리자가 권한을 얻지 못하는지 실제 RLS/Edge로 검사한다.

## 검사 범위
실제 로컬 회원가입/비밀번호로그인, 관리자RLS조회, 익명/비관리자 RLS차단, 직접RPC차단, 실제Edge 비인증/비관리자/미승인 차단, 승인된합성신청 Edge생성, 저장plan/job 식별자일치, 중복재사용, 6단계 및 awaiting_approval, 모의주석분리, 결과테이블별 비관리자차단. 외부Claude는 호출하지 않음.
이 실제 로컬 통합이 통과해도 운영 소유계정/운영Auth/운영Edge배포/운영고객데이터 PASS로 확대하지 않는다. 비용원장 자체는 이전PASS재사용이며 본 로컬RPC는 유료호출전 예약 어댑터가 아니다. 모의 주석 저장만 한다.

## 환경 기동 중 해결한 문제
초기 workflow는 job env에서 사용할 수 없는 runner.temp 표현식 때문에 실행되지 않아 /tmp 전용 경로로 수정했다. 이후 CLI 공식 바이너리 설치/해시/로컬설정 생성까지 성공했으나 이미지 다운로드가 ECR의 toomanyrequests: Rate exceeded로 실패해 DB포트 연결 거부가 뒤따랐다. Auth 로그인 실패나 운영권한 문제로 해석하지 않는다.
전체 원문 대신 민감한 줄/URL/긴불투명값을 제거한 제한된 기동 진단만 확인했다. Supabase 공식 setup-cli 소스 src/main.ts에서 SUPABASE_INTERNAL_IMAGE_REGISTRY=ghcr.io 사용을 확인해 공식 GHCR 미러를 지정했다. 외부인증·레지스트리로그인·한도증액·유료서비스가 필요하지 않은 대안이다. 같은 다운로드를 무한재시도하지 않는다. 아직 실행되지 않았던 로그아웃 응답 처리도 HTTP204 빈본문을 허용하도록 바로잡았다. 실제 API 재시도 로직을 추가하지 않았다.
