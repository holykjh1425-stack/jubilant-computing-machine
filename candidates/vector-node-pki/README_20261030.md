# SOLQ OpenSSL executable dependency replacement candidate

Baseline: b55ade9735854b946059080b905801e3f58890d3.
Branch: dev/solq-vector-node-pki-20261030. Original vector-real files remain unchanged.

## Decision

Use the existing Node.js crypto implementation, without installing openssl.exe,
npm packages, PowerShell modules, or modifying Windows certificate stores.
Node crypto still uses Node's embedded crypto implementation; this is not a
claim to remove cryptographic library dependencies from Node itself.

Node exposes key generation and signing, and X509 parsing/verification, but does
not expose a general-purpose certificate issuance convenience function. This
candidate encodes a deliberately fixed X509 DER profile and signs it using
Node's RSA-2048/SHA-256 implementation. It is only for this ephemeral local test,
not a production CA or an arbitrary CSR/certificate issuance service.

Windows New-SelfSignedCertificate is another official option, but normally
touches certificate/private-key stores and needs an additional safe export and
cleanup path. It is not used here. No OpenSSL installation is required for the
recommended candidate, so no installer or PATH change is proposed.

## Scope

- New one-day CA and localhost/127.0.0.1 server plus client identities.
- Critical CA/basic constraints and key usage; serverAuth/clientAuth separation.
- The issuer key is not returned. Leaf keys exist in process memory only.
- No PEM/PFX/key file is created by the new certificate provider.
- The driver best-effort overwrites returned key Buffers at shutdown; native
  TLS/KeyObject copies cannot be proven erased before process exit.
- Private result directory ACL, fixed named pipe, loopback19443, single attempt,
  empty container allowlist, ping/version-only probe remain unchanged.
- proxy.mjs and legacy-policy.ts are byte-identical to b55ade9.
- Existing approved lifecycle still requires the explicit -ApproveLocalReadProxy
  switch. Default invocation performs no Docker/PKI/listener access.

## Windows prerequisites and one authorized execution

Existing Node22 or newer with TypeScript stripping support and docker.exe.
Windows PowerShell5.1, current-user writable LOCALAPPDATA on an ACL-capable disk.
Existing desktop-linux context, 14 containers, stopped/no-restart Vector and
13 running peers. Loopback19443 must be unused. No admin elevation/installation.

Download the fixed candidate commit archive after the Windows CI evidence is
recorded. Extract it, inspect the candidate file hashes, then run from:

    <extracted repository>\candidates\vector-node-pki

    & .\Invoke-SolqReadProxy.ps1 -ApproveLocalReadProxy

Do not rerun if a prior live probe was attempted: the user's one-shot approval
does not authorize automatic retries. Prerequisite checks that stopped before
Docker access are not a successful or completed real probe. Preserve any prior
result and obtain separate approval if a real attempt actually failed.

On error stop; never bypass execution policy or install dependencies automatically.
Only the probe prints sanitized JSON/result folder. Do not send keys or raw Docker
inspect output. Success requires READ_PROXY_PASS, equal before/after fingerprints,
and no cleanupIncomplete. Existing Vector remains stopped; it is not recovered.

Rollback: stop only this foreground probe using Ctrl+C if necessary; no existing
Docker objects were created/changed and no configuration rollback is needed.
The new provider writes no key files even on interrupted execution. Native process
memory cleanup remains OS-managed. Preserve result.json; dedicated cleanup script
only removes its own marker/result directory with an explicit cleanup switch.
