- 수동 새로고침 및 선택형 60초 주기 조회를 구현했다. 단일 요청 묶음만 실행하고 이전 응답을 무효화한다. 연속 실패 3회에 자동 조회를 중단한다. 수동 재시작을 지원한다.

## 점검 기록

- v1 `solq-control-local-review-v1` 원문은 읽기만 한다. 삭제·덮어쓰기·자동 가져오기를 하지 않는다. 원본 JSON 내려받기를 제공한다.
- 새 기기 초안은 `solq-control-local-drafts-v2`에 저장한다. 담당자(미인증), 판정 제안, 점검 시각, 차단 원인, 다음 조치, 증거, 변경 전후를 기록한다. 이것은 운영 승인·서버 감사 로그가 아니다.
- 파일 URL·다른 브라우저·다른 Origin·다른 기기의 로컬 저장소는 자동 접근할 수 없다. 원본 환경에서 내려받아 보관해야 한다. 현재 후보는 자동 이관 기능을 제공하지 않는다.
- `reviews.candidate.sql`은 **운영 미적용** 설계다. 새 테이블 solq_control_reviews(추가 전용)와 solq_control_writers(별도 작성 권한)만 만든다. 고객 테이블의 권한은 추가하지 않는다.
- 관리자만 기록을 읽고, 별도 writer 관리자로 등록된 사용자만 새 버전을 추가한다. 행위자는 인증 uid와 일치해야 한다. UPDATE/DELETE/TRUNCATE 권한을 부여하지 않는다. RLS·만료·단조 증가 버전·유일성·동시 변경 충돌·증거 링크 제약을 적용한다. PASS는 사실·다음 조치·점검 시각·https 증거가 필요하다. 기록은 관리자 진술이며 시스템 실검증을 자동 증명하지 않는다.
- 서버 이력 조회는 최근 200개로 제한하고 전체/일부를 구분한다. 과제별 서버 최신 이력을 표시하지만 200개 밖 과제의 기록은 누락될 수 있으므로 기존 기록을 최신 서버 상태로 단정하지 않는다.
- 저장 응답이 불확실하면 자동 재시도하지 않고 이력 재조회를 요구한다. 추가 전용 장부는 사용자에 의한 과거 이력 덮어쓰기를 막지만 DB 소유자의 변조까지 방지하는 외부 감사 원장은 아니다.

## 비용과 갱신 선택

이번 작업의 유료 API·추가 서버·유료 프로젝트·배포 0. 현재 추가 비용 발생 0원. 로컬 npm 잠금파일의 기존 의존성만 설치했다.

기존 Data API를 60초 간격으로 조회하는 방식을 우선 제안한다. 정상 1회는 원천 조회 9회 + 전후 getUser/관리자 확인 4회 = 약 13회 HTTP 요청이다(세션 확인은 로컬). 계속 열린 화면 8시간 최대 약 6,240회/일이다. 조회 완료 후 60초를 기다리므로 오래 걸릴수록 횟수는 낮아진다. 정확한 계정별 요금·DB 부하·egress는 실제 사용량 점검 전 확정할 수 없다. 승인 후 소규모 측정이 필요하다.

Realtime은 이번 후보에 넣지 않았다. 테이블 publication·subscription 정책·연결 수·수신 범위·권한 만료 처리를 추가 검토해야 한다. 필요한 기존 상태에 바로 접근하는 폴링이 변경 범위가 작다. Realtime이 항상 더 저렴하거나 안전하다고 판정하지 않는다.

## 운영 승인 및 롤백 순서

1. 보호된 최소 권한 점검 결과를 검토하고 별도 권한 정리안을 승인한다. 이 후보는 기존 권한을 임의로 변경하지 않는다.
2. 기존 보호 환경에서 실제 관리자/비관리자 Auth 경로 검증. 인증 우회나 임시 관리자 등록 없이 확인한다. 실제 고객 연결 전 필수다.
3. 서버 기록이 필요하면 후보 SQL의 새 2개 테이블·RLS·추가 전용 trigger 적용과 특정 writer 계정만 등록하는 범위를 별도 승인한다. 적용 전 기존 같은 이름이 없는지 확인한다. 마이그레이션 파일은 승인 후 현재 CLI로 생성한다. 기존 고객 데이터 변경은 포함하지 않는다.
4. 기존 운영 배포 자산/Source를 확인하고 같은 Origin의 관리자 후보에만 필요한 파일 추가를 승인한다. 운영 URL/사이트 ID가 확인되기 전 추정하지 않는다. 기존 admin/index/worker/cron 수정은 제외한다.
5. 승인 후 LIVE_READ_ENABLED와 단일 프로젝트 CSP 접속 허용을 검토하고 시험한다. SERVER_REVIEWS_ENABLED는 새 테이블 적용·writer 검증 후에만 별도로 켠다. 실제 부하·실인증·회귀 증거 확인 후 활성화한다.
6. 롤백은 새 조회 갱신을 중단하고 두 gate를 false 및 CSP 잠금 상태로 되돌린 뒤 이전 사이트 버전/정적 파일로 복귀한다. 고객 행 복구는 필요하지 않다. 서버 장부는 삭제하지 않고 신규 작성 권한/접근만 승인 범위 내 중단해 보존한다. 실제 운영 롤백은 미실행이다.
