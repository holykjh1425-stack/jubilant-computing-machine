## 데이터 계약과 통제
신청행 FOR UPDATE와 application_id UNIQUE, job.plan_id UNIQUE로 동일 신청당 한 쌍. 생성은 승인된 합성 신청만 허용. 6단계는 기존 순서를 유지하고 job은 awaiting_approval만 허용한다. 계획 생성과 실제 제작/납품은 다르며 실행 코드가 없다.
Claude 분석은 annotations에 분리하고 계획 steps를 수정하지 않는다. SQL상 순서 일치, 토큰 입력0..1000/출력0..512, nanoUSD 계산, 총원장 cap<=US$0.001 확인. 원장 charge+계획+작업+주석은 같은 트랜잭션에서 commit/rollback한다.
이 fixture SQL은 **이미 반환된 모의 결과의 원자적 저장 검사**다. 실제 유료 호출 전 예산 예약/사용량 불명 hold/분산승인 원장은 기존 budget-candidate.sql/Windows 증거를 재사용하며 본 fixture를 대신 사용할 수 없다. 외부 API 실행 후 DB rollback이 과금 취소를 뜻하지 않는다. 실호출 미포함이므로 자동재시도 경로도 없음.
장애 주입 후 복구 재호출은 외부 호출이 전혀 없었던 합성 DB 트랜잭션만 대상으로 한다. 실제 API timeout 재시도 승인과 다르다.
운영9/6/7건 및 역사적 중복 기록을 읽거나 쓰지 않았다. 따라서 최신 운영 건수/지문 재확인을 주장하지 않는다. 실제 DB 저장 PASS는 합성 PostgreSQL에 한한다.

- 실제 Supabase Auth/관리자 권한: 승인된 비운영 프로젝트/사용자 세션이 없음. 이전 운영 PC 인증 PASS는 재사용하되 비운영 통합 PASS로 전용하지 않음.

- 운영 설정 변경 없이 실제통합하려면 기존 비운영 Supabase 또는 보호된 로컬 Supabase stack의 URL/접근권한/서버측 secret 관리 경로가 필요하다. 현재 그러한 자산은 연결 도구에서 확인되지 않았다. 새 유료인프라는 준비하지 않음.
