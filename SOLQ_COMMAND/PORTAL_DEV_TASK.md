## 작업 2 — 격리 개발 후보 코드 작성
1. 기존 상담→신청→접수번호→관리자 조회→무료 6단계 계획→견적·입금 확인→별도 제작 승인 흐름을 개발용 후보로 연결한다.
2. 실제 신청 원본과 접수번호의 일대일 대응, 동일 키/동일 본문 재시도, 동일 키/다른 본문 거부, 응답 유실, 충돌, 실패 시 거짓 성공 방지의 서버 계약을 구현 또는 독립된 후보 파일로 제시한다.
3. 관리자·고객·익명 역할 경계와 RLS/저장소 접근 통제를 후보 SQL/코드로 구현한다. 실제 Supabase에는 적용하지 않는다. 운영 키/비밀번호/토큰 포함 금지.
4. 무료 6단계 계획은 기존 규칙형 엔진 재사용을 기본으로 하고, 실제 AI 연결은 서버 측 교체 가능한 인터페이스만 만든다. 기본 provider=mock/rules, 실제 API 키/유료 호출/자동충전/외부 전송은 모두 OFF. 고객에게 실제 AI 사용 중이라고 허위 표시하지 않는다.
5. 견적·입금·제작 승인 3단계가 완료되기 전 제작 워커/유료 실행/외부 발송은 불가능하도록 fail-closed 설계한다. 승인 이벤트를 모의 시험하고 실제 결제·제작은 실행하지 않는다.
6. UI는 390px 모바일과 데스크톱을 지원하고, 네트워크 실패·저장 결과 불명·중복 제출을 명확히 표시한다.
7. 개발 파일을 신규 후보 경로에 추가하거나 개발 브랜치에서만 수정한다. 원본 파일 삭제 금지, 운영 배포 자산·데이터 덮어쓰기 금지. 마이그레이션은 REVIEW_ONLY / NOT_APPLIED 명시.
