# SOLQ COMMAND — DEV-05 운영 준비 차단 해소 / 읽기 전용 검증

기준: DEV-04 보고서 90169d913b318f80579effd7aefde6a6f6c700c7 및 공동 장부 4657c758d886edf2ee14b3d09c011de3c7c350ba
권한: READ_ONLY_EVIDENCE_AND_RELEASE_READINESS_PLAN / executionAuthority=false / launchStatus=NO_GO

## 목표
기존 Windows 환경의 독립 비운영 인스턴스와 별도 복원 후보를 권한 있는 담당자가 읽기 전용으로 식별하고, SOLQ 실제 운영 준비의 미검증 관문을 증거 중심으로 정리한다. 이전 PASS는 반복하지 않는다.

## 작업 A — Windows DEV-05 환경 식별
1. DEV-03/04 로컬 증거 및 기존 T01·P1 기록을 먼저 읽고 중복 조사를 피한다. 권한 없는 보호 폴더를 우회하지 않는다.
2. 권한이 있는 로컬 Windows 담당자가 기존 서비스/프로세스/실행 토큰 SID/실행 파일 경로/데이터 경로/ACL/포트/포트프록시/활성 방화벽 정책을 읽기 전용으로 조사한다. 관리자 권한 상승이 필요한 명령은 실행 전에 권한과 범위를 명시하고, 불가능하면 BLOCKED를 유지한다. 비밀, 토큰, 고객 데이터, 전체 실행 인수를 출력하지 않는다.
3. Windows P1 합성 데이터, 보존된 T01 원본, 과거 Docker 클러스터, 운영 Supabase를 명확히 구분한다. P1의 소유권/상속 ACL과 실제 전용 계정 유효 권한을 별도 판정한다. 과거 Docker 와일드카드 포트/비내부 브리지 기록을 안전성 증거로 사용하지 않는다.
4. PostgreSQL 17.11 기존 원본 후보 1개와 원본과 경로/포트/계정/클러스터가 분리된 기존 복원 후보 1개를 찾는다. 발견하지 못하면 '없음'으로 단정하지 말고 '확인 불가/미입증'으로 기록한다. 어떠한 DB 시작/접속/SQL/백업/복원도 실행하지 않는다.
5. Auth/PostgREST/Storage의 실제 기존 실행 파일·서비스·버전·DB 대상·스토리지 경로가 있는지 확인한다. TOML 활성 플래그와 과거 Docker 설정만으로 설치·동작 PASS 판정 금지.

## 작업 B — 운영 출시 관문 증거 장부
1. GitHub 기존 코드/보고서에서 공식 solqtech.com -> 개인정보 안내 -> 신청 -> 접수번호 -> 관리자 인증/조회 -> 원본 보존 경로를 읽기 전용으로 추적한다. 실제 웹 요청이나 운영 DB 접근 없이 코드·링크·환경 설정의 정적 근거와 미검증을 구분한다.
2. 견적 100,000원/착수금 30,000원, 관리자 입금 확인 및 별도 제작 승인, 중복/동시성, 무료 6단계 계획, 고객 A/B/관리자/익명 권한 분리의 정적·기존 합성 검증과 실제 통합 미검증을 구분한다.
3. 백업 범위(DB·Auth·Storage·Edge·설정), 암호화 백업 및 독립 복원, RPO/RTO, 보안 경고, 회귀·롤백·관측·개인정보 보관/삭제 요청, Google Play 등록 등 운영 관문을 PASS/BLOCKED/NO-GO로 정리한다. 실제 개인정보/고객 데이터는 읽지 않는다.
4. A(읽기 전용 식별) -> B1(합성 원본 백업) -> B2(별도 복원) -> C(합성 PostgreSQL SQL) -> D(Auth/API/Storage 통합) -> E(운영 배포 전 심사)의 별도 승인 표를 작성한다. 각 단계별 대상·명령·계정·포트·쓰기·복구·비용·중단 조건을 명시한다. 확인되지 않은 값은 TBD, 실행 금지로 표시한다.
